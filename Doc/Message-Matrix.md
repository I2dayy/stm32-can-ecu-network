# CAN 通信矩阵

三节点车载 CAN 网络的报文定义。基于 STM32F103C8T6 + bxCAN，标准帧（11 位 ID），500 kbps，DLC 固定 8 字节，小端字节序。

## 节点

| 节点 | 角色 | 行为 |
|---|---|---|
| A | 动力 ECU | 周期发送转速、车速、油门、水温 |
| B | 车身 ECU | 周期发送门锁、灯光、雨刷；每 5 次附带一帧诱饵报文 |
| C | 组合仪表 | 只接收 `0x100` 与 `0x200`，通过硬件验收滤波屏蔽其他 ID |

## 报文清单

| CAN ID | 名称 | 发送节点 | 发送周期 | 接收节点 |
|---|---|---|---|---|
| `0x100` | EngineData | A（动力） | 500 ms | C（仪表） |
| `0x200` | BodyData | B（车身） | 1000 ms | C（仪表） |
| `0x400` | ReservedFrame | B（车身） | 每 5 秒一次 | 无（用于验证滤波） |

## EngineData（0x100）

动力系统状态，500 ms 广播一次。真车对应发动机 ECU 广播的转速/车速信号。

| 字节 | 信号 | 类型 | 缩放 | 偏移 | 物理范围 | 说明 |
|---|---|---|---|---|---|---|
| 0–1 | EngineSpeed | uint16 | 0.25 rpm/LSB | 0 | 0–16383.75 rpm | 小端，低字节在前 |
| 2–3 | VehicleSpeed | uint16 | 0.01 km/h/LSB | 0 | 0–655.35 km/h | 小端，低字节在前 |
| 4 | ThrottlePosition | uint8 | 0.5 %/LSB | 0 | 0–100 % | 节气门开度 |
| 5 | CoolantTemp | uint8 | 1 °C/LSB | −40 | −40–215 °C | 冷却液温度 |
| 6–7 | Reserved | uint8 | — | — | — | 保留，固定 0 |

**打包公式**（原始值 → 总线值）：

```
Byte0 = (rpm * 4) & 0xFF
Byte1 = (rpm * 4) >> 8
Byte2 = (kmh * 100) & 0xFF
Byte3 = (kmh * 100) >> 8
Byte4 = throttle_pct * 2
Byte5 = temp_c + 40
```

## BodyData（0x200）

车身状态，1000 ms 广播一次。真车对应车身控制器广播的门/灯/雨刷状态。

| 字节 | 信号 | 取值 | 说明 |
|---|---|---|---|
| 0 | Door | 0 = CLOSED，1 = OPEN | 车门锁状态 |
| 1 | Light | 0 = OFF，1 = ON | 灯光状态 |
| 2 | Wiper | 0 = OFF，1 = ON | 雨刷状态 |
| 3–7 | Reserved | 固定 0 | 保留 |

## ReservedFrame（0x400）

车身节点每 5 秒发送一次的无关报文，`Byte0 = 0xAA`。仪表节点的硬件滤波器不放行此 ID，因此该帧不会进入接收 FIFO，也不会产生 CPU 中断。用于演示和验证验收滤波机制。

## 接收滤波规则

仪表节点（C）使用 bxCAN 的 32 位列表模式过滤器，只放行两个 ID：

```
过滤器 0：IdList 模式，32 bit
  条目 1 = 0x100 << 5
  条目 2 = 0x200 << 5
  目标 FIFO = FIFO0
```

11 位标准 ID 在 32 位过滤器寄存器中左移 5 位对齐。不在名单上的 ID（如 `0x400`）由硬件直接丢弃，CPU 不感知。

## 备注

- 报文周期相对真车已放慢（真车动力 CAN 典型为 10 ms），仅便于串口观察。
- 所有多字节信号采用小端字节序（低字节在前）。
- 定点数通过缩放与偏移转换为整数传输，接收端按表中系数还原为物理量。
